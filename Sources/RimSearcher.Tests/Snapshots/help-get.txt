Usage: rimsearcher get <defName> [options]

Show one def in full: its identity, its fields, and any translations of it.

Field paths are the merged, post-patch shape the game actually had in memory when the snapshot was taken, so PatchOperations and inheritance are already applied. A def created in code rather than XML says so on its source line.

The 'source' line is the bare file name the game reported for that def — no directory, because the game does not keep one. It names the file inside that mod's Defs folder ('mod' above says which mod); it is not a path, and nothing here reads the file system to confirm the file is still there. Defs the game builds in code carry a placeholder there instead.

Arguments:
  <defName>  The exact def name. 'search' finds it if you only know part of it.

Options:
  -n, --limit <n|all>   How many fields to return. Use 'all' for no cap. Values above 2000 are clamped to 2000. Default: 60.
                        Also accepted: --max-results, --count, --top, --rows, --num, --head.
      --path <text>     Only show field paths containing this text. Repeat it to widen the selection.
                        Also accepted: --paths, --field, --field-path, --only, --filter, --grep.
      --type <DefType>  Restrict results to one def type, for example ThingDef or HediffDef.
                        Also accepted: --def-type, --kind, --category.
      --defaults        Also list fields whose value is the one a fresh instance of the declaring type already carries. Those rows are left out by default because they are the ones most often read as something an author chose, when the snapshot cannot tell whether anything set them at all. How many were left out is always printed, and --path shows a named field either way.
                        Also accepted: --with-defaults, --all-fields.
      --fields          Deprecated no-op: fields are always shown. Kept so that scripts that pass it keep working.
                        Also accepted: --with-fields, --show-fields.

Global options (every command takes these, written after the command):
      --snapshot <name>  Query this named snapshot instead of the one that would be picked automatically. An explicit choice always wins over auto-detection.
                         Also accepted: --snap, --env.
      --db <path>        Query the snapshot database at this path directly, bypassing the registry.
                         Also accepted: --database, --snapshot-path.
      --json             Emit machine-readable JSON. Anything the text output would have said in prose moves into a 'notes' array, so nothing is lost. The command's own table key is always present — an empty array when nothing matched, never a missing key.
      --config <path>    Use this config file instead of the default one.

--json keys (besides 'notes'):
  defs  one object per def carrying the name — each with 'def' (identity), 'fields' (path/value rows) and, when there are any, 'translations'. It stays an array even for a single def, because a name can belong to several def types at once.

Examples:
  rimsearcher get Apparel_ShieldBelt
  rimsearcher get Apparel_ShieldBelt --path statBases
  rimsearcher get Bullet_Revolver --limit all
  rimsearcher get Bullet_Revolver --defaults
