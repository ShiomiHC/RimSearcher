# 快照：如何制作，何时重做

选哪份快照来查询，主页已经写明。本页写其余部分：快照如何产生，同一名字的各世代如何轮换，以及不匹配检查的局限。

## 如何制作

`rimsearcher export --modlist <名称>` **在没有窗口、没有图形设备的情况下运行游戏**：启动 RimWorld，加载 mod 名单，转储内存中的每个 def，然后退出，因此才说「导出时在内存中」。stderr 上的停滞报告表示某个阶段有一段时间没有进展，并写明停滞多久；此后游戏**继续运行**，直到超时，超时时长见导出命令自己的帮助，`rimsearcher export --modlist <名称> --timeout <秒数>` 可以加长。运行恰在两种情形下提前结束：游戏自己的日志说数据加载失败（此时游戏被停止，加长 `--timeout` 无济于事），或者你中断它。游戏没有交回导出文件时（它无法启动、数据加载失败、在超时处被停止，或退出时没有写出文件），`export` 以退出码 `69` 退出，而不是 `2`，原因写在 stderr 上。

## 各世代，以及何时由重新导出替换文件

重新导出同一名字，旧文件轮换为 `<名称>.prev`，再之前的轮换为 `<名称>.prev2`，依此类推；配置文件中的 `snapshot_keep` 或 `--keep <n>` 决定该名字保留多少世代（计入正在写入的那一份），超出该数的都会删除，并说明删除的是哪些。`snapshot list` 把一个名字的较早世代折进 `较早世代数` 一列；`snapshot list <名称>` 把它们逐一列出。只有当新到的库在每张表中逐行相同时，重新导出才会让每个世代都保持原样：包括布局，以及导出所记录的一切（游戏版本、语言、带加载顺序与版本的 mod、导出器版本与各项上限），运行本身留下的痕迹除外。查询在检测到不匹配时会自行提出，但这项检查比对的是大小与时间戳，所以保持两者不变的编辑会不被察觉。`Languages/` 下的编辑只由输出译文的命令（`keyed`、`get`、`search`、`list`、`economy`）提出，以一张 `languages` 表呈现，并且只限于在记录这一项之后导出的快照（`snapshot status`，`语言文件指纹` 一行）。断定工具有误之前先重新导出：`rimsearcher export --modlist <名称>`，其中 `<名称>` 必填，取自 `rimsearcher modlist list`。
