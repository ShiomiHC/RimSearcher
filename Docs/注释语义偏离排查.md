# 注释语义偏离排查

呈现层重构（见 [呈现层重构指导.md](呈现层重构指导.md)）收尾后的一条尾账。**这份文档是给另一个会话冷启动用的**：
下面写清了已经排除掉什么、还剩什么、以及为什么剩下的那部分不能自动化。

## 1. 这是什么

「语义偏离」指：注释描述的行为与代码实际行为不一致，但**两边都读得通**——注释里引用的标识符全在、
数字全对、规则编号全有定义，只是那句话说的事情代码已经不做了。

例：注释写「按名序取前 N 个」，而代码改成了按分数排序；注释写「三分支」，而代码已经是四分支。

这类偏离**没有任何一道闸拦得住**：
- 编译器不看注释；
- 887 个测试（含 59 份字节级快照）钉的是输出，注释错了一个字都不会红；
- 本项目的注释承载的是**判据**（为什么这么写、盲测里踩过什么坑），偏离一条就等于把一条判据变成假证词，
  而下一个改这段代码的人正是按它做决定的。

第 1、2 维的扫描脚本可以这样复现（PowerShell，跑一次约 10 秒）：

```powershell
# 维度 1：注释里的 Foo.Bar，Bar 在所有非注释代码里都找不到
$src = "S:\works\CS\RimSearcher-src\Sources"
$files = Get-ChildItem $src -Filter *.cs -Recurse | Where-Object { $_.FullName -notmatch '\\(bin|obj|\.build)\\' }
$code = New-Object System.Text.StringBuilder; $hits = @()
foreach ($f in $files) {
  $lines = Get-Content -LiteralPath $f.FullName
  for ($i = 0; $i -lt $lines.Count; $i++) {
    if ($lines[$i] -match '^\s*//') {
      foreach ($m in [regex]::Matches($lines[$i], '\b([A-Z][A-Za-z0-9_]{2,})\.([A-Za-z_][A-Za-z0-9_]{2,})\b')) {
        $hits += [pscustomobject]@{ At = "$($f.Name):$($i+1)"; Ref = $m.Value; Mem = $m.Groups[2].Value }
      }
    } else { [void]$code.AppendLine($lines[$i]) }
  }
}
$t = $code.ToString()
$hits | Where-Object { $t -notmatch ('(?<![A-Za-z0-9_])' + [regex]::Escape($_.Mem) + '(?![A-Za-z0-9_])') } |
  Sort-Object Ref -Unique | Format-Table -AutoSize
```

第 4 维只要一条 grep：

```bash
grep -rn --include="*.cs" -E "//.*(修好时|修好之后|届时|会作为 diff 出现|将来|尚未|仍未|待修|钉的是\*\*现状\*\*)" Sources
```

## 3. 剩下的部分为什么不能自动化，也不该拉 workflow

语义偏离的判据是「这句话说的事，代码还做不做」——要回答它必须**同时**理解注释描述的意图和代码的实际行为，
再判断两者是否同一件事。这三件事里没有一件是文本匹配能替代的。

不要拉并行 agent 做这件事，理由是具体的：

- **删错不会红。** 这是唯一一类改动，做错了 887 个测试全绿、编译零警告，要到几个月后有人按那条假判据改代码时才爆。
  本项目其余所有改动都有闸（字节级快照 + GrammarRules 常驻），唯独这一类没有。
- **判据是跨文件的。** 一条注释常在说另外三个文件里的事（`Fold.Explicit` 的注释在讲 `RoslynHelper` 够不到命名空间；
  `ScanReport` 的注释在讲三处联动）。局部 agent 只看得见一个文件，看不见那条耦合，于是最容易把
  「说的是别处」误判成「说的是这里，而这里没有」。
- **本项目的注释本身是资产。** 33251 行代码 5036 行注释（15%），零处注释掉的死代码，只有 12 行 `///`。
  这些注释记的全是「为什么」和盲测里的真实误读记录，不是可以按密度削减的噪音。
  **任何以「精简 / 清理注释」为目标的批量改动都是负收益，正确的目标只有「让它说的与代码一致」。**

具体做法建议：一次一个文件，读注释 → 读它旁边的代码 → 只问一个问题「这句话说的事，这段代码还做不做」。
不确定的就去 `Output/` 下找那个判断现在的家，看注释描述的分支数、顺序、条件是否还对得上。

## 7. 干活前要知道的两条规矩

- **构建前先停 MCP server**：`RimSearcher.Server` 进程锁着 `.build` 输出，不停会 MSB3027。
  `Get-Process -Name RimSearcher.Server | Stop-Process -Force` 之后立刻 build（它会自动重连并跑新二进制）。
- **先立闸再改代码**：这是本项目贯穿呈现层重构的方法论——要改的行为先补一份字节级基线（在改动前的代码上生成、
  单独提交），改完拿它比 diff。纯注释改动无此需要，但一旦顺手动了代码就适用。

```bash
dotnet test Sources/RimSearcher.Tests/RimSearcher.Tests.csproj -v q --nologo
```

基线：**880 通过 / 0 失败 / 7 跳过**，合计 887（2026-07-29）。跳过的 7 条全是 Windows 专属
（junction 建不出、`PlatformFacts` 的两条），**59 份字节级快照一份都不跳**——故在 Linux 上跑出来的
「零 diff」与在 Windows 上等价，这条线的判据不受平台影响。
