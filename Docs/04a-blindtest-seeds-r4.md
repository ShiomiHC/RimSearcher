## 一 · 前置闸(不过就别跑)

1. **exe 必须是最新的**。改完代码不重发布,PATH 上还是旧的,盲测测的是旧二进制。
   ```bash
   dotnet publish Sources/RimSearcher.Cli/RimSearcher.Cli.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none -o "$env:USERPROFILE\.rimsearcher\bin"
   ```

   凡是新增了 db 表/列的改动,都要逐个快照验一遍,不要只验 pinned 的那个。
3. **`rimsearcher-dev` MCP 若在跑,会锁住构建输出**,发布前先停。

### 缺陷簇(按代价,不按数量)

**已生产错结论的:**

1. **干净、计数明确、无警告的表,而它是错的** —— 唯一直接产出 nearly_wrong 的簇。
   四种机制:子串匹配不留痕(`get X --path soundImpact` 只回 `soundImpactDefault`,
   语义相反,`code_default=no` 让它看着像作者刻意设的)/ null 值字段整条路径不入索引,
   与「字段不存在」同形 / 兄弟字段够不着(`minFuelCost=50` 盖掉 `fuelPerTile=3`,16 倍)/
   同显示标签跨 def 类型不交叉提示。
2. **零结果说谎或不分流** —— 11 张面孔。`values --scope` 说「本快照没有」而不带 scope
   有 63 个;`find` 不跨快照兜底(races 里明明有 6 个);`search` 不索引译文 original 侧,
   中文快照上英文全盲;把未验证的「如果 X 是抽象基类」摆在输出位置(而工具自己一条
   `code-search` 就能证伪);`types --scope` 0 行却 exit 0,破坏退出码约定。
3. **C# 默认值 ↔ def 实际值之间没有拐回提示** —— 正向:从类声明读到 `= true` 就当
   六个 def 都是 true(实际全部 XML 写死 False);反向:判别字段的 `code_default=yes`
   是正常且唯一正确的状态,照文档字面读会把正确结果全丢掉。
4. **「vanilla」一词三义** —— 叫 vanilla 的快照(2 mods)/ `--scope vanilla`(6 个
   Ludeon 模块,含 DLC)/ 用户嘴里的原版。差点造成 22 倍错误。
5. **崩溃** —— `search dull --snapshot vanilla` → exit 70。模糊回退按 def_name 建字典
   没去重(`AllDefNames` 的 SQL 无 `DISTINCT`),快照里有两个 Drill 就炸,
   且崩在「不知道确切名字先 search」这条主推入口上。

**结论无法证实的:** 截断注脚自己算不准(报 251/242 而全库总数 239,**报数大于总数**);
索引口径的洞(磁盘资源、Keyed 翻译、`<li Class=>` 运行时类型、def 的原始 XML 文本)
没有任何一处划线。

usages / overrides / derived。

### 三个二阶发现(方法论,比缺陷清单更耐用)

- **自责会把 cost 从「后果成本」偷换成「恢复成本」。** 9 条 `my_own_mistake` 里 6 条
  应改归工具。归工具时算「这条把答案带偏多远」,归自己时只算「我爬回来花了几条命令」。
  **全卷复现率最高的缺陷类恰好拿到最低定价** —— 因为每份轨迹只看得见自己那一次,
  而那一次看起来总像「我图省事」。跨轨迹复现次数才是「正常人会不会在同一处栽同样跟头」
  这条判据能拿到的最强证据。**逆着自评复核这一步不能省。**
- **把候选清单发回轨迹做反事实自评,能推翻清单本身。** 这一轮推翻三处落点,
  全部是没读产地就写的,而三处真相都**比清单更窄更便宜**:
  ① 「`NameLookup.Locate()` 就是共享层」不成立 —— 被四份点名为最佳输出的那句六路排除
  是 `GetCommand` 在 `Locate` 返回 null 时的 fallback,接线既拿不到它又会覆盖掉
  `find` 自己那句同样被点名的好话;
  ② `inherit` 的无名节点**不是不打印** patch_ops,是打印一个与「量过了确实没人 patch」
  同形的硬 0 —— 比原描述更坏,而导出器注释写着「宁可多报,漏报会让人以为没被动过」;
  ③ 截断注脚报数大于总数的真因在调用侧的**按路径逐条求和**,结果里只要有一条路径叫
  `defName`,后缀匹配就命中每个 def 类型,这一项独自等于全库。
- **两条定价规则。** 更便宜的选项通常是 Pareto 优而非妥协(七处同形;上下文预算是
  LLM 调用方的第一约束,输出侧每加一行都在所有调用上收税);schema 级改动一票也不给
  (拿一份轨迹的摩擦买一次全量重导,是把别人的账单记在自己头上)。

### 反事实自评还挣出的次序依赖(没人报、复核自己看出来的)

- **修 `search` 崩溃必须排在「译文 original 侧兜底」之前** —— 两者共用 `ByNames`
  那条路径,次序反了等于给崩溃开第二个入口,而那次入口是中文快照上的英文查询。
- **页脚区分快照内外,只加注不缩范围。** 若顺手实现成「默认只扫快照内的树」,
  三份轨迹的穷举论证同时作废,**而降级前后输出一模一样** —— 本轮候选里最危险的同形。
- **注脚算准之后「沉默」会变成担保**,而它只保证「没有**已知**的同类型截断」
  (导出器是停手不是数完)。静默时仍要留一句,别让修计数把认识论诚实顺手修掉。
- **「收窄开关缺失」的高复现是注脚算错的派生量** —— 十份里九份跑 `snapshot truncated`
  是被那个错注脚逼去核销的。先修注脚,再重新数。

### 八份一份都没问的那件事

**`snapshot status` 那句「与当前安装的游戏完全一致」到底比了什么。**

原文自己把范围列全了 —— `same mods, same order, same version`,即**加载清单**,
不是磁盘上的数据。八份的用法:ep180 把它当成「快照 = 现在的游戏数据」,据此对
**用户刚刚编辑过自己 mod 文件**这件事下了否定判决(「你的改动没有生效」)——
而那恰好是这个比较**结构上不可能察觉**的那一类改动;ep50/69/15 把它写进作用域声明
当成「结论覆盖用户当前游戏」的许可证;其余三份默认继承。

**与上一轮 33 棵树 vs 23 棵树同形:工具把自己的口径老老实实印在输出里,
八个人一致地把那句自我限定读成了一句背书。**

同形但轻一档的第二候选:截断脚注的数字按 `--scope` 过滤,而它推荐的 `snapshot truncated`
不过滤 —— 同一件事实测印成 2 / 3 / 58 / 239 四个数,四份轨迹当同一个概念互相替换着写。
