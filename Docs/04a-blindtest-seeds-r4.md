## 一 · 前置闸(不过就别跑)

三条都是实测过会毁掉整轮的:

1. **exe 必须是最新的**。改完代码不重发布,PATH 上还是旧的,盲测测的是旧二进制。
   ```bash
   dotnet publish Sources/RimSearcher.Cli/RimSearcher.Cli.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none -o "$env:USERPROFILE\.rimsearcher\bin"
   ```

   验:`rimsearcher <新命令> --help` 出得来,且 exe 时间戳晚于最后一个提交。
2. **快照必须含被测层**。第三轮跑之前查过 `modded.db` 的继承层在(导出于 af97809 提交前
   3 分钟,代码已写完),但 `vanilla.db` 导出更早(02:53),**很可能没有继承层** ——
   凡是新增了 db 表/列的改动,都要逐个快照验一遍,不要只验 pinned 的那个。
3. **`rimsearcher-dev` MCP 若在跑,会锁住构建输出**,发布前先停。

> 背景:我在给自己 mod 的光束类武器补「打到目标那一下」的音效,已经照着原版投射物的

> 到底会不会被播放?请给出明确的会/不会,并指出决定这件事的具体位置(哪个类型的哪个方法,
